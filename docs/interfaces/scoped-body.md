# Interface: Scoped document body

**Status:** accepted  
**Provider:** `apps/api` (scopes before return)  
**Consumers:** `apps/web` renderers / editors that display body HTML or AST

## Rule

Renderers never learn who the viewer is. The document body arrives already scoped for the viewer. No per-viewer body cache that would require re-scoping client-side.

**Owner ruling, 2026-10-11:** enforce per-viewer blocks on every readable document, including SQL NULL and JSON-null `policy`. Preserve the whole-document gate and author/admin raw-body bypass. A legacy DM or archon whole-document grant does not bypass a block addressed to another member; archon does not imply literal `role:dm`.

## Provider

API applies audience policy and marker rules before returning body content. The product readers for direct ID/slug, lists, directory, batches and typed quest briefs use `document.ProjectDocumentView`. Quest and DM summary readers use that same projector with one hydrated `ViewerScope`, including `ReaderOf`, shared with their SQL readability arguments. Character summaries return metadata only and apply `document_readable` to both their list and count queries with the same reader grants. This is the shared **Specification** and projection pattern, converging on one authoritative audience rule. Outer denial returns no body, and an inner marker cannot re-grant that document. Each hidden span becomes the `> [!redacted]` line followed by its rough shape, per [D45](/docs/decisions/D45-Redaction-Keeps-Rough-Size.md) (owner decision 2026-10-28, superseding the earlier no-length-hint rule). The text-line count is exact, and marker-only lines add none. Each hidden text line becomes one `> █…` line, its rune length rounded up to the next multiple of 20 and capped at 200 bars. Blank lines stay `>`. Past 100 shape lines, one `> +N more lines` count replaces the rest. One projection draws at most 10,000 bar runes, in span order; after that, hidden spans show only the marker and their line count. When the next span starts with content, a blank line ends the placeholder, so the content never joins the redaction's quote. The server generates the shape. Renderers draw it as bars and never receive the hidden text. Author/admin bypass retains the raw source; actual administrator override is logged without protected body, policy or handle principals.

The closed grammar is recorded in [D20](/docs/decisions/D20-One-Closed-Marker-Set.md), including the accepted July 30 lexical amendment, and the shared `audience-markers.v1.json` vectors. The closed forms are `[!dm]`, `[!dm:@handle]` and `[!spoiler]`, with case/outer whitespace folding, exact handle case and marker charset `[A-Za-z0-9_.-]+`. Spoiler is presentation only. A blockquote run includes following nonblank quote lines and lazy continuation lines. An ATX heading, list item, code fence or thematic break with up to three leading spaces ends the run, as does a line starting with `<` after optional spaces or tabs. The server classifies the whole run once with the existing marker precedence: malformed known markers deny the run, otherwise the first member handle outranks DM, and DM outranks spoiler. These grouping rules apply inside lists too. Bare markers retain their line-only scope.

**Owner decision D2, 2026-10-29:** an accepted marker on a line that is not a blockquote start produces the server-authored `LIST_NESTED` diagnostic when the line begins with `>` after optional indentation and an optional bullet or numbered list prefix. The diagnostic leaves projection unchanged. It locates the marker separately from projection spans and warns that the marker does not protect the whole list item. Editor warnings and publish confirmation consume that diagnostic; Cancel preserves the draft without publishing. A structural list warning has no token-only replacement. `TestAuditBodyWarnsForListNestedAudienceMarkers`, `TestAuditBodyIncludesLazyContinuationLines`, `TestScopedQuoteLazyMarkersUseExistingPrecedence`, `TestScopedQuoteLazyContinuationStopsAtNewBlock` and `requires confirmation for list-nested marker warnings` enforce these boundaries. This extends the server's single classification surface without adding client audience policy.

**Observed scoped verification (2026-10-11):** the full offline Go `./...` suite passed. The bounded native Go integration run passed against PostgreSQL 16.14 using the recorded audit-only database lifecycle adapter; this does not verify the unchanged Docker/Testcontainers lifecycle. Native assertions passed for all 42 SQL NULL/JSON-null × visibility × viewer leaves, five body projections (direct ID, slug, list, codex directory and typed quest brief), and the separate batch path. Four current-authority transitions with unchanged JWT also passed. The denial cases checked `FORBIDDEN`, empty readable enumeration/counts, no body values or raw fragments, and an empty batch; readable cases checked complete expected text and hidden-sentinel absence. Astra's independent v2 review recorded zero must-fix findings for the frozen body source and fixture.

These historical results close the prepared native body assertion boundary for that slice. At that body-slice verification, the repository-wide `scripts/verify` local-cache run stopped at `format:check`; that dated observation is not the current repository verification verdict. Later repository checks have their own source/evidence boundary and do not broaden these body assertions. The renderer/editor consumer remains unverified, as does the original Docker/Testcontainers database lifecycle. Search currently emits title snippets; backlinks and map places emit metadata, and none of those is a body projection. Public archive ingestion, other body-bearing domains and editor/save behavior remain outside this document-body slice.

**Source consolidation, 2026-10-29:** legacy Document ID/slug/list readers, their batch wrapper and request scope cache are removed. Product queries retain direct reads, scoped enumeration, batches and discovery. Backlink assertions use product list/count SQL and the codex entry’s `backlinkCount`. Mounted revision/trash protocols retain their exact author/admin gates. `ProjectDocumentView`, its shared `projectDocument` boundary, `SQLViewer`/`SQLScope` and the live reader-grant query remain. This source change does not renew the historical database execution receipt above.
