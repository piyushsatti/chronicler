# Requirements — Round trips, not connections, are what the frontend pays for

System: [frontend.md](/docs/systems/frontend.md)

## Requirements

| #   | Requirement                                                      | Because                                                                                                                                                                                                                  |
| --- | ---------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| R1  | The frontend is a static Vite/React app served from Vercel.      | Same-origin Vercel rewrites route API requests to the environment's API. Production and staging use separate API origins.                                                                                                |
| R2  | TCP connection setup and request round trips are separate costs. | Vercel and the selected backend path determine connection behavior. Measure real page loads before setting a request or connection budget. The current routing plan does not establish latency or multiplexing behavior. |

## Assumptions

| #   | Assumption                                                                                                                                                                      | If wrong                                                                                                                                                                                                                                                                                                                                                                         |
| --- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| A1  | The deployed frontend and API path allows common page requests to complete without a long serial waterfall                                                                      | Unmeasured. Use a network trace of a real page load to assess request concurrency and latency (`GQL-CONN-2`)                                                                                                                                                                                                                                                                     |
| A2  | A mutation author's hand-written `invalidateQueries` list is complete for every surface currently rendering the entity                                                          | It is not, confirmed live: `arc.quests[]`'s nested quest copies are never invalidated by `useSignupForQuest`, and the same bug shape reproduces anywhere an entity is denormalized into a sibling's cached response                                                                                                                                                              |
| A3  | The browser's per-origin connection limit does not turn Home's roughly 11 parallel hook-mounts into a de-facto waterfall                                                        | Unmeasured; a network trace of a real Home load, not code reading, is the only way to confirm this (Loading and performance)                                                                                                                                                                                                                                                     |
| A4  | A cached, already-redacted document body bounded only by `gcTime`/`staleTime` is an acceptable proxy for "this content is still owed to this viewer"                            | It is not guaranteed to be: nothing invalidates a scoped body on a mid-session authority change, so the cache TTL, not an access decision, currently bounds how long stale privileged content can render. Caching server-decided per-viewer content client-side, scoped only to session, rebuilds the shape [`D4`](/docs/decisions/D4-Scoped-Body-Cache.md) rejected server-side |
| A5  | Errors staying uniformly generic (per the `#266` ruling) is the right default even for the one failure class the viewer could act on: their own permission changing mid-session | If Data and caching's R5 resolves the other way, actionable-but-still-safe error content becomes a requirement instead of a rejected option                                                                                                                                                                                                                                      |
