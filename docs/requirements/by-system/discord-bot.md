# Requirements — Discord bot

System: [discord-bot.md](/docs/systems/discord-bot.md)

## Requirements

| #   | Requirement                                                                                                                                                                   | Because                                                                                                                                                                                                                              |
| --- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| R1  | The bot's capability set is a short, explicit, named list, exactly what it may forward and nothing else, stated on this page, not inferred from reading `src/bot` end to end. | Today's answer ("3 gateway events, read-only, one REST call") only exists as scattered code comments; `Authorization.md`'s boundary table names the bot as a machine boundary but states no capability set, and defers that to here. |
| R2  | Every event the bot forwards is idempotent against Discord's at-least-once redelivery, at the backend, not the bot.                                                           | Already true for `message`/`voice` via the `uuid5` claim; `reaction`'s millisecond-timestamp id is a documented exception to this requirement, not an instance of it.                                                                |
| R3  | Announce content obeys the same redaction specification as every other surface that renders a document body, with one specification, not a parallel implementation.           | `quest_announce_v2.py` already calls the same `redact_dm_blocks` function `Documents-and-audience.md` audits; this requirement is that page's R3 applied to the announce surface, not a new rule invented here.                      |
| R4  | Bot downtime degrades one named thing (activity telemetry) and is visible as that, not silent.                                                                                | Today it is silent: no alert, no dashboard, no CD gate ties to sniffer liveness.                                                                                                                                                     |
| R5  | Identity is minted in exactly one place, and every other consumer of a Discord id reads that mapping without creating it.                                                     | Already true (`ensure_member` is the sole mint point); stated as a requirement so a future write path can't quietly become a second mint point.                                                                                      |
