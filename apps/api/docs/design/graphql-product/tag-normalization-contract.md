# D9 normalization specification

**Status:** accepted design. Published schema/config and comment scaffolds do not implement these contracts. Runtime enforcement remains pending the owning implementation tasks and their tests.

Governing patterns: specification and set-based SQL with streaming reduction. D9 explicitly requires live distinct values, Go-compatible casefold, unchanged text[] storage, and no canon table, migration or backfill. PostgreSQL lower() is not the matching interpreter.

Q08 implements FoldKey as strings.Join(strings.Fields(value), " ") followed by the golang.org/x/text/cases.Fold v0.42.0 (the current pinned module). The display candidate is the whitespace-normalized original, without casefold. Reject blank tokens and more than100 input tokens; each normalized token is at most200 Unicode code points. Deduplicate input fold keys retaining first input order.

For a write, call NormalizeVocabulary once with both tags and genres, forming one union of (kind, foldKey) for both kinds (genre precedes tag for deterministic canonical processing), deriving signed 64-bit advisory lock IDs from a fixed vocabulary namespace plus those complete pairs, deduplicating identical resulting lock IDs, then acquiring the IDs in ascending signed numeric order. Sorting actual lock IDs rather than separately sorting each kind prevents lock cycles even under digest collisions; collisions only serialize unrelated keys and never change matching. The lock ID is the signed two's-complement int64 interpretation of the first8 big-endian bytes of SHA-256 over UTF-8 `chronicler:vocabulary:v1`, NUL, kind, NUL, FoldKey. Execute pg_advisory_xact_lock in the sorted ID sequence (at most200 distinct IDs); these are bounded lock calls, not per-token vocabulary lookups. No command acquires a further vocabulary lock after this set. Then one set query streams live tags or genres with quest.created_at, quest.public_id and array ordinal in that exact ascending order. Fold each candidate in Go and retain the whitespace-normalized display spelling of the first stored candidate for each requested key. Do not materialize all candidates in application memory. The streaming reducer retains at most100 requested keys/canonical matches. Reuse matched casing after whitespace normalization; existing raw token strings stay untouched; if no match exists, retain normalized first input spelling. This ordering resolves preexisting variants; historical token authorship is unknown. Concurrent absent-key writes are ordered by lock and commit: a later writer reuses the first committed spelling; rollback leaves no spelling authority.

Genre/tag read filters use the same FoldKey against live values. One streamed set lookup produces distinct matching stored spellings, then the page query uses text[] overlap against those exact spellings. The variants represent values, never a hash to reverse. The set lookup retains at most1MiB of matching distinct spellings; exceeding the execution resource bound returns an opaque dependency failure and no results, rather than truncating or widening the predicate. QuestsSpec and QuestStateCountsSpec carry internal TagFilterSet/TagVariants/GenreFilterSet/GenreVariants populated only by ProductQueries; callers cannot supply prepared values through GraphQL. An explicit filter with no variants produces zero rows and total0. All valid casing variants match; unrelated values do not. Do not substitute SQL lower(), ASCII-only folding or a curated token table. Query and command use the same Q08 primitive. Candidate query and command have the documented three-second statement deadline; timeout is a dependency failure with no empty-success fallback. No per-token SQL lookup is permitted.

Acceptance Q08 includes whitespace dedup, stored casing/legacy whitespace variants, deterministic preexisting variant ties, concurrent first-commit and rollback, and Unicode Straße/STRASSE folding to the same match key. Filtering either spelling returns both legacy-variant quests in normal scheduled/UUID ordering, with exact full authorized total. This document is the authoritative normalization mechanism; existing behavior.md normalization prose must remain aligned with it.

Legacy whitespace fixture (exact strings):

```text
stored raw token: "River  Road"
input: " river road "
```

The raw token matches the input; the new writer persists `River Road` (casing preserved, whitespace normalized), and leaves the old row/token untouched. MatchVariants still returns both exact raw stored values after that write, so the SQL overlap filter matches both old and new quests. This is normalization of the new write, not a vocabulary-table backfill.

The planned Q08 NewTagNormalizer(db dbgen.DBTX) binds the executor explicitly: W01 constructs the command adapter with the exact business pgx.Tx. W02 injects QUE04 NewTagReadTaskRunner(pool) into QUE05 NewProductQueries. QUE05 calls TagReadTaskRunner.Do with a callback receiving TagReadScope{Reads,Tags}. QUE04 constructs both ProductReadRepos and NewTagNormalizer on one repeatable-read read-only transaction. The callback resolves variants then page/count through those same bound repositories; Do rolls back/releases on completion. The singleton ProductQueries never retains the task executor. No remote I/O runs in that task. Neither caller supplies a hash or a hidden executor. QUE06 uses the single two-kind normalization call, never two separately ordered calls. Q08 tests reversed input kind order concurrently, verifying identical global lock order and no deadlock; a rollback preserves both original arrays.
