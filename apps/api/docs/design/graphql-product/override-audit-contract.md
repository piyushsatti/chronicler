# Actual override audit — D29

**Status:** accepted design. Published schema/config and comment scaffolds do not implement these contracts. Runtime enforcement remains pending the owning implementation tasks and their tests.

Governing pattern: shared authorization specification plus safe structured observation for reads and transactional audit for writes. D29 requires actual override distinction, not a new mandatory authored reason. No implicit bypass permits player-character mutations or addressed request decisions.

P02 Policy.Decide returns Allowed, UsedOverride and a safe closed RuleCode: ROLE, OWNERSHIP, ASSIGNMENT or AUDIENCE. RuleCode identifies the predicate skipped; it contains no protected policy/body. An ordinary action allowed without bypass sets UsedOverride false. Caller-independent validation never sets UsedOverride. No RequiresReason flag exists.

Read services receive OverrideReadObserver through their exact constructors. W02 supplies P02 NewSafeOverrideObserver(slog.Logger), using the application's configured structured logger. After an actual permitted bypass, the query service emits OverrideFact{ActorID,Operation,SubjectType,SubjectID,RuleCode,At} using its captured clock; no database mutation, receipt, history or grants occur during reads. DOC05 scoped-body bypass retains the existing safe observation semantics and must emit through this same observer, not duplicate protected payload logging. Logger output is diagnostic, not a second durable authority or a successful product action.

Command ProductCommandRepos.Audit.Record(ctx,OverrideFact) binds the SAME business transaction in W01. P02 owns its implementation and persisted auth_override_audit writer; P04 owns auth_override_audit(id bigint identity, public_id uuid unique, actor_id bigint FK members, operation text, subject_type text, subject_public_id uuid, rule_code text, recorded_at timestamptz), restricting rule_code to the four values. Subject UUID is an audit identifier, never body or policy data. Any audit write failure rolls back the overridden business/history/notifications/job/receipt. No human reason is invented, required or reconstructed. Operations with real authored note/reason fields retain them in their existing owned history, and redrive specifically still requires its V27 reason.

S03 mounted audit vectors: anonymous/read-denied document011 yields FORBIDDEN and no override log; author002 ordinary read yields no override log; live admin004 reads otherwise denied011 and emits one safe AUDIENCE fact for that read evaluation, zero database changes, no HIDDEN_BODY_SENTINEL/policy/tokens in captured logger. Demote004 before next request: same read denies and no successful override observation. For editPublishedDocument admin004 on010 with the exact PATCH-DOCUMENT-EDIT-JOINT input, persist one audit fact with original actor/operation/subject UUID and frozen clock in the business transaction; forced audit insert failure leaves original Document/history/notification/receipt unchanged. P02 exclusive companion exercises RuleCode/UsedOverride; S03 owns mounted boundary assertions. Staff/admin/platform owner claim of031 or edit/sync of another player's Character is FORBIDDEN with no audit implying override, even on a replay key. Addressed request decision remains exclusive to003, with no override for admin004/platform owner017.

Mounted exact payload/fact/recipient/rollback criteria are in mounted-override-cases.json; new audit/revision/event IDs are captured UUID variables, not seeded outcomes.
