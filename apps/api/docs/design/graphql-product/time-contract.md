# Time-owned materialization and calendar projection

**Status:** accepted design. Published schema/config and comment scaffolds do not implement these contracts. Runtime enforcement remains pending the owning implementation tasks and their tests.

Pattern: CQRS with a materialized read table, calibration points and an anti-corruption layer for the two existing definition shapes. Spatial Time is one authority. Readers never interpolate anchors or rates. This specification targets backend Time R1–R5; calendar routes/frontend rendering R6 remain outside the no-web scope.

## Definition and date rendering

One Time parser accepts the canonical QA legacy shape `{epoch:string,months:[{name:string,days:int}]}` and the existing admin shape `{era:{name:string,abbrev:string},periods:[{name:string,type:month|festival,days:int}],days_per_week:int,weekdays:[string],leap:null,rate_real_days_per_game_day:number,moons:[{name:string,cycle_days:int}]}`. The raw authored definition remains the persisted and returned JSON; parsing yields one normalized Time-owned period sequence. If both legacy and modern period sequences are present, reject INVALID rather than choosing an interpreter. Period count1–36, names1–200 characters, days1–366, sum at most3660. Era strings1–200; modern abbrev1–32. Days-per-week1–32 and weekday count matches; metadata rate finite positive<=100; moons<=20, cycle days1–3660. Omitted optional metadata remains omitted, never synthesized into returned JSON. Legacy eraAbbrev returns the literal epoch label, explicitly a compatibility wire name rather than an invented abbreviation. Modern eraAbbrev returns literal era.abbrev.

The existing documented backend formats and admin preset supply leap:null; this contract accepts null/omitted leap and rejects nonnull unknown leap rules INVALID. It does not claim an undocumented leap-rule interpreter. Moon/weekday/rate metadata is stored and returned exactly for display, while anchor.rate alone governs real-to-game trajectory; changing display metadata does not advance game_time_map. No consumer creates a second rate interpreter. Any accepted future leap grammar needs an explicit Time contract change with exact fixtures, rather than being ignored.

For a stored integer game_day g, year length L=sum period days. Compute zero-based year index floor(g/L), within-year day g-floor(g/L)*L, year=index+1. Find the first period whose cumulative upper bound exceeds that within-year day. Return periodIndex zero-based, literal name/type, day one-based. This works for negative g without truncation toward zero. No epoch offset is inferred. These are calendar-format calculations over a stored game_day, not live real-to-game conversion.

Designed synthetic calendar delta: era{name:Pi Era,abbrev:PI}, periods[{name:River,type:month,days:30}], leap:null. Stored game_day113 returns `{eraAbbrev:PI,year:4,periodName:River,periodIndex:0,periodType:month,day:24}`. The canonical QA legacy definition has four30-day months Thaw/Salt/Harrow/Ember and epoch Year of the Kept Tower; stored214 returns that literal era label, year2/Ember/index3/month/day5. These are independent fixture expectations and must not be recast as a live provider/production calendar receipt.

## Reads

`gameDate(realDate)` performs the exact map lookup then Time definition rendering. No map row returns null without error, including a legitimate g=0 row which returns the first day rather than being mistaken for absence. Mapping exists but missing/malformed definition is opaque INTERNAL, not a fabricated date. Dependency failures always propagate.

`gameCalendar(realFrom,realTo)` requires realFrom<realTo and at most366 UTC dates, includes realFrom/excludes realTo. monthGrid is one `{realDate,gameDay}` cell per requested date in ascending date order; uncovered rows have null gameDay. Each cell's gameDate is rendered by the resolver-backed monthGrid through the same RenderStoredGameDate(day,definition) as currentGameDate; it is null when the cell's gameDay is null, no definition exists, or the stored definition cannot render, so monthGrid never fails on the definition. currentGameDay/currentGameDate independently use the injected clock's current UTC date. Reads never fill missing cells. Definition is the literal singleton JSON; absent singleton yields null definition/currentGameDate, while available map currentGameDay remains factual. A malformed stored definition fails opaque INTERNAL only at the selected nullable currentGameDate field; definition/currentGameDay/monthGrid remain factual and readable. That field is resolver-backed through SPA05 RenderStoredGameDate(day,definition), which uses the same pure parser; the base calendar DTO does not eagerly render it.

`realDates(gameDay,limit,offset)` reads every actual reverse match, real_date ascending; total before pagination, [] when no rows. `timeAnchors` is staff-gated and orders real_utc ascending then UUID ascending. No ordinary calendar consumer sees anchors or repeats trajectory math.

## The single writer

SPA06 owns the Time materializer; SPA04 owns only the corresponding persistence methods, with no commit. Anchor creation/edit and calendar updates use the same command uow. Worker FillFuture uses the receipt-bearing borrowed-connection scope in work-contract.md. All writers serialize the Time aggregate by a transaction advisory lock before anchor/calendar/map access. Worker additionally holds the physical by-kind session lock, but no path takes that lock after acquiring the Time transaction lock. No HTTP is held in either scope.

For each UTC midnight date in [today,today+horizon), select latest anchor real_utc<=that midnight, tie-break public UUID descending for any preserved legacy duplicate. New create/edit rejects another anchor at the same real_utc with CONFLICT under the Time aggregate lock; no historical duplicate is silently deleted. Zero rate pauses the trajectory and is valid; negative/NaN/infinity reject INVALID. Rates must be finite, >=0 and<=100, epoch_day int32. Calculate `floor(epoch_day + elapsedNanoseconds/(86400*1e9)*rate)` in one Time implementation: convert persisted float64 with strconv.FormatFloat(rate,'g',-1,64) to decimal big.Rat, use exact rational elapsed UTC duration, mathematical floor including negatives. Reject int32 overflow atomically. Do not use truncation, float-error epsilon or Unix-date fallback. No eligible anchor for any requested date is expected INVALID for the manual trajectory write; maintenance parks that job as repair_required with TIME_ANCHOR_UNCOVERED on the first attempt instead of retrying it to dead (#49). All proposed changes roll back. A first anchor must cover current UTC midnight; future calibrations are admissible when an earlier anchor covers the horizon.

N2 supersedes non-Document anchor/calendar history described below; no such history table or write is retained. N8 supersedes effect observations: the borrowed Time writer uses Jobs Admit/Recheck fencing in the current work-contract refinement, without an observer sink. Foreground commands and the borrowed writer share the same private Time parser, projection and persistence methods; no second interpreter is introduced.

Regenerate only dates>=the injected current UTC date; past map rows remain byte-for-byte unchanged even after backdated anchor edits. Upsert only changed game_day values and count actual admitted inserts/changes, not attempted rows. Repeating the same projection yields0 changes and no duplicate effects. Anchor history records immutable exact old/new input, actor, time and captured history UUID; creation prior value null. Failed projection/history/receipt rolls back anchor plus map/history together. Calendar definition update records old/new JSON/actor/time, changes date rendering only and does not invent another clock trajectory. Its command response monthGrid uses [today,today+30), explicitly bounded without a hidden read argument.
