# Go interface freeze (design only)

**Status:** accepted design. Published schema/config and comment scaffolds do not implement these contracts. Runtime enforcement remains pending the owning implementation tasks and their tests.

Governing patterns: modular monolith, CQRS, unit of work, specification, request loaders and set-based SQL. The single exact declaration inventory is go-seams.json. interfaces.json records root service methods. These inventories are design declarations; they are not executable scaffolding or proof of implemented behavior.

Domain packages own their DTOs, command specs, locked state, write requests and repositories. DTO primitives and relationship IDs cross aggregate boundaries; graph field resolvers hydrate relationships through the named provider. Domain packages never import graph. Shared product types contain only infrastructure/value types. ProductQueries and ProductCommands are the authoritative services; the source dispositions must remove or narrowly adapt legacy methods without a second command interpretation.

Each command receives current resolved Authority and validates current capability plus current owning-aggregate ownership/admission before returning any replay receipt. It then admits the actor/operation/key receipt and canonical fingerprint. A matching completed receipt replays before one-time target existence, lifecycle, expected-version or transition preconditions; those business preconditions apply only to a genuinely new execution. Current authority or ownership denial still prevents receipt disclosure, including after live demotion/revocation. One uow.Runner.Do owns the transaction and binds all local and foreign writers through app.ProductFactory. Repositories never commit. Policy assignment lookup and audit writes use that same transaction for commands. Reads and batch providers own individual task connections, with no request-wide database lock. External DDB and webhook calls hold no database transaction or borrowed query connection.

Nullable stored provenance remains pointers. product.Optional[T] distinguishes omitted patch input (Set=false), explicit null (Set=true,Value=nil), and supplied value. Returned collections are non-nil empty slices, never synthetic constant placeholders. Every repository result derives actual persisted values and current audience-scoped relationships.

Site HomeSpec and SiteStatsSpec carry internal IncludeActivity intent derived from gqlgen collected field selections, including aliases, fragments and directives. Counts and activity use separate named SQL queries. Region and map list capabilities use one actor-assignment lookup through PoolPolicyProviders and Assignments, then a list-local Policy copy retains the ordinary decision interpreter, lieutenant delegation, denial, override and provider-error behavior. No global authority cache is introduced.

Auth.Policy.Decide(ctx, actor, request) consumes a closed auth.Request created by the exact operation-specific factories in auth/policy.go. Owning loaded facts cannot confer privilege. NewPolicy requires task-bound Assignments, Audience, Identities and SummaryRelationships providers. Character mutation and exclusive addressed-DM restrictions derive from the exact operation registry, never caller-selected flags. Document alone evaluates its Specification and scoped-body projection; its AudienceAssessment preserves exact batch correspondence and one real same-population override subject for safe read observation, including count-only or empty-page activation. Lieutenant collection SQL always applies the full author/assignment admission predicate before count and pagination. No runtime JSON policy interpreter or second Document parser is introduced. Configured platform owner is immutable optional UUID, validated and resolved active at boot; absence grants no owner privilege. Live authority remains mandatory. Same-request mutations invalidate authority-sensitive loaders; later mutation fields resolve authority again after commit. Retained HTTP protocols preserve their Problem envelopes; GraphQL authority boundary emits its specified GraphQL error envelope.

Concrete notification.Producer implements the consumer-owned notification.EventProducer interface; Record has one signature in go-seams.json. Command repositories hold that interface, never a pointer to an interface. Commands generate stable immutable fact IDs before writer calls, pass those IDs in typed write state, and feed the same fact IDs to the producer and receipt. It never reconstructs decision/revision/change facts from current state. Producer recipient selection, preferences, event insertion and recipient insertion share the business transaction; required inbox failure rolls back the whole action. Reward claims emit no new notice.

Participation admission, promotion and retirement follow participation-locking.md; Character rows are locked before Quest rows, including promotion candidates. Quest closure writes PCXP entitlements. Claim locks Character then sorted Quest/entitlement rows. Quest supplies validated entitlement IDs, amounts and claim status to Character; Character never queries Quest tables. Character appends its existing progression ledger and cached balance. The exact entitlement→new-ledger-ID bindings flow to Quest MarkRewardClaims in the same transaction. No staff or platform-owner bypass permits claiming another player's reward.

Each request loader has a concrete comparable key with all actual normalized predicates and pagination values. Provider Batch methods receive those values directly; no fingerprint reversal or mutable hidden filter registry exists. Duplicate keys preserve input/result correspondence. Alias differences in status/role/pagination produce independent cached values. Pointcrawl edge providers suppress edges incident to a hidden location node under the same Document audience predicate used by node/link providers.

Maintenance uses by-kind advisory execution exclusion for bounded DB-only logic, plus receipt validation inside the transaction that admits effects. Token fencing alone does not claim physical single execution. Schema gate is read-only effective Goose version logic. Observations are projections of the single background work authority. The outage monitor is ephemeral and handles only DB_UNAVAILABLE, with at-least-once alerts across restart. No second durable queue exists.

check-go-seams.py scans fields, state, writes, methods, constructors and provider seams for unknown qualified types and import cycles. Its receipt does not establish Go compilation or runtime correctness. Final provider/caller/task ownership and mounted behavior audits remain independent Gate 1 requirements.

DOC04 implements one ReadableDocumentIDs set query under the canonical Document audience specification. Document-owned and Notification consumer-owned interfaces have identical signatures and the same implementation; they avoid a Notification↔Document import cycle. Character guild IDs, Quest brief references and Spatial linked references are suppressed when unreadable; malformed policy or lookup failure propagates as opaque failure. They never become silent false/read-empty success. Character commands use Document GuildReader for new guild association validation; existing readable legacy references are retained without category rewriting.

D9 read variants and page/count retrieval execute through QUE04 TagReadTaskRunner.Do(scope), with one read-only repeatable-read task snapshot and bound Q08 adapter. Command adapters bind the business transaction; NormalizeVocabulary receives both arrays once and takes the deduplicated global numeric advisory-lock set. Immutable owner admission lookup is nonlocking before participation planning. D5 dmTable is a Document-owned lazy set loader, never Member profile fallback; dm-table-contract.md and mounted-dm-table-cases.json define its exact producer, privacy and uniqueness effects.

D29 actual overrides use `auth.OverrideFact` and a closed safe `RuleCode`. Queries retain the configured structured observer and perform no audit database writes. Commands bind `NewOverrideRecorder(replay)` to their same transaction-bound replay repository and call `Record(ctx, actualClaim, fact)`. The existing `Complete` writes the ordered six-field `_authorizationOverrides` facts beside the command result in its single conditional receipt update. Current authority precedes replay, and completion failure rolls back the entire business UOW. No audit table, independent audit UUID, or mandatory user reason is introduced. `override-audit-contract.md` defines the exact storage, replay, and mounted acceptance requirements under the owner's 2026-10-20 decision. Earlier missing-table failures remain historical evidence.

Scheduled effect admission crosses through Jobs-owned EffectGuard.Admit/RecordAdmitted in the exact borrowed-connection transaction. EffectPermit is opaque outside Jobs, and Jobs alone rechecks the post-lock database clock. Lifecycle public UUID and internal receipt-row identity are distinct. Spatial receives ConnectionRunner/LifecycleObserver explicitly; it never reimplements receipt validity.

## Authoritative semantic provider amendments

The final callable declarations are generated in go-seams.json. display-state-contract.md owns the single Quest SQL specification and injected AsOf contract. rewards-and-policy.md owns nullable actual claimed-PCXP totals and full-closure coverage. Document DiscoveryReader owns search, safe snippets, feed and counts for Site. notification.ProducerRepos composes owning Character, Document, Quest and Social recipient readers on the exact business transaction. NOT04 never queries foreign aggregates to reinterpret their rules. DOC06 passes canonical resolved new-mention IDs in typed notification.Facts. NOT08 applies event-kind recipient rules, deduplication, actor exclusion and preferences. It cannot parse body text or invent historical IDs. Notification.Event.Facts is typed until NOT04 serializes it into storage.

Replay admission may load the retained owning aggregate including its tombstone solely to check current ownership/capability; this grants no ordinary public tombstone read. Original delete/close/restore results remain replayable when that same action changed the lifecycle. Character log deletion checks the current retained Character owner from characterId before receipt admission; a matching receipt binds the original actor/characterId/logId fingerprint, so the now hard-deleted log row is not required to disclose its original receipt. A new key must still prove the log exists and belongs to that Character before any fresh deletion. Never infer ownership of a missing log from the log UUID, skip current Character admission, or disclose another actor receipt. These are the already required same-key Character/Quest replay cases, not a new role or lifecycle bypass for fresh commands.

## Consumer contract lock (2026-10-17)

The consumer build target is the full recursively discovered repository SDL. Its current inventory has 164 root fields across seven domains. That count describes the published wire contract. It does not approve additional operations that lack an accepted decision. Unfinished implementation does not reopen the whole interface. Runtime acceptance remains separate.

Three clauses remain explicit. `DocumentType.readerIds` is a nullable list for users authorized under the existing Document audience-management rules. They receive an empty list when no readers exist. Other viewers receive null without reader IDs. Its resolver guard, provider, and nested resolver tests remain pending, so generated code must not hydrate the field publicly by default. `adminOperations.deliveries.historicalRoleNotificationMissed` is deferred because reliable historical evidence is unavailable; no false or current-health substitute is valid. The Character mapping for `description` and `backgroundText` remains unresolved. The current SDL keeps their nullable `String` input types and omits `= null` defaults on `UpdateCharacterProfileV2Input` per the accepted two-line patch in commit `d49396b`.

These clauses follow the 2026-10-17 owner-approved batch. The current operation inventory remains subject to the separate resource-level CRUD audit.
