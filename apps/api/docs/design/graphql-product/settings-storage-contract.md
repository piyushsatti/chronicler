# Typed settings migration

**Status:** accepted design. Published schema/config and comment scaffolds do not implement these contracts. Runtime enforcement remains pending the owning implementation tasks and their tests.

Pattern: anti-corruption layer for one bounded migration, followed by one typed storage authority. This is a new engineering import contract, not a claim that old writers used any particular payload key. Actual 0001 member_settings has only member_id, theme_mode, timezone, payload JSONB NOT NULL and updated_at. P04 must not DROP nonexistent cosmetic columns or call the following missing columns retained.

P04 adds these NOT NULL columns and defaults: theme TEXT 'parchment' CHECK IN(parchment,midnight,ember,dracula,vegan); mode TEXT 'system' CHECK IN(light,dark,system); effects_enabled BOOLEAN TRUE; colorblind_safe BOOLEAN FALSE; reduced_motion BOOLEAN FALSE; density TEXT 'comfortable' CHECK IN(comfortable,compact); notify_character_verification, notify_quest_signup, notify_document_activity, notify_quest_scheduled, notify_dm_mentioned, notify_dm_request_decided BOOLEAN TRUE each. These include the actual seven missing colorblind/preference columns. timezone and updated_at are retained literally. Existing rows are updated through the following preflighted mapping before dropping theme_mode, all in one migration transaction.

Only exact physical snake_case and current wire camelCase names are recognized for each newly added column; identical names are one key. No other aliases are inferred. For Boolean keys, absence or JSON null uses the explicit default; a nonnull value must be JSON true/false, preserving false. For theme/density keys absence or null uses the default; present nonnull must be a string in the declared lowercase storage set or exact uppercase GraphQL enum set; map the latter to its matching lowercase storage value. This bounded two-representation adapter adds no case-insensitive or alternate spelling acceptance. When both aliases contain nonnull values, normalize and require equality. A null alias is absent for choosing between aliases: one nonnull value wins over the other null; both absent/null use the default. Conflict between two nonnull values or malformed type fails preflight before any schema/data commit, reporting only Member public ID/key and safe reason, never the opaque payload. mode comes ONLY from actual theme_mode: NULL→system, exact light/dark/system retained, any other value preflight failure. payload.mode is historical opaque content, not an alternate mode authority. timezone comes only from its actual nullable column, with no payload interpretation or invented timezone normalization during migration.

Keep the entire payload JSONB value unchanged, including recognized keys, unknown keys, pronouns and table_notes. JSONB value equality is the preservation invariant; PostgreSQL JSONB has no original lexical byte ordering to preserve. Retain export copies in the existing migration fixture/export lane. After migration every live read/write uses the typed columns only, never payload fallback or shadow updates; this opaque retained value is historical data and has no second settings API. updates to one typed flag leave all other columns, payload and unrelated rows unchanged. P04 preflight inspects actual cosmetic catalog values/dependencies before the already approved cosmetic purge; it cannot drop absent columns or guess retained achievement labels. Down restores original theme_mode from mode and preserves payload; export/fixture restore is required to recover purged data and pre-migration typed representations. Data loss on down is explicitly declared.

P04 acceptance uses real migrated rows for: empty payload defaults; false/true/null in every recognized flag; equal aliases; conflicting aliases; invalid scalar types and enum values; mode light/dark/system/NULL and invalid; retained timezone and updated_at; opaque pronouns/table_notes nested JSON preserved by equality before/after/up/down. MEM04's settings mapper reads all twelve new columns exactly; MEM06 patch writes no payload. S03/S04 settings joint/query fixtures use these physical columns only after 0003. Each rejected preflight proves the original schema and all rows unchanged; final settings write failure rolls back typed columns/history/receipt. Tests do not infer database success from parsing this contract.
