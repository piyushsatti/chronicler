## Borrowed connection and admitted effects

The by-kind execution gate acquires one pool connection and retains its session advisory lock until its bounded callback returns. It passes `jobs.ExecutionScope{Receipt jobs.Receipt, Connection *pgxpool.Conn}` to the callback. The connection is borrowed only for that callback; consumers neither release it nor retain it. `TimeFillWriter.FillFuture(ctx, scope, from, days) (int32,error)` and `ConsistencyChecker.Check(ctx, scope)` run their one unit of work on that same connection through the DB01 connection runner. They never acquire a second pool connection. The runner alone begins, commits on nil, and rolls back otherwise; repositories never commit. Pool size one is therefore a required acceptance configuration. External HTTP is excluded from this callback.

`jobs.LifecycleFact.EventKind` distinguishes lifecycle state transitions from `EFFECT_ADMITTED`; `EffectCount` is the actual changed map-row count for that effect. The time transaction checks the current receipt token, running state, lease/deadline and compatibility before any effect and immediately before commit, appends the effect observation in that transaction, and returns the actual count. An expired or reclaimed token returns its expected fenced failure and zero committed map/history/observation effects. Finish fencing is additional and cannot authorize a stale time write.

DB01 owns `apps/api/internal/platform/db/connection_runner.go` and its disposable-DB companion. Its exact facade is `Run(ctx context.Context, connection *pgxpool.Conn, fn func(pgx.Tx) error) error`, exposed through `db.ConnectionRunnerFactory`. Acceptance uses max-connections one, pauses token1 before effects, expires/reclaims token2, resumes token1 and requires zero effects; a nil callback commits exactly once, callback failure rolls back, the session lock remains held through transaction completion and the gate releases its own connection only after unlocking.
