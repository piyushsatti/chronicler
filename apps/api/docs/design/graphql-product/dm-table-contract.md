# DM table — D5 preserved

**Status:** accepted design. Published schema/config and comment scaffolds do not implement these contracts. Runtime enforcement remains pending the owning implementation tasks and their tests.

Governing patterns: Document aggregate with specification, partial unique constraint, and request-scoped set loader. This converges on Document authority. Member dm_profiles.table_info is a different structured profile value; it does not replace a table document.

DOC06 createDocument supports kind community/category dm_table under existing Document author authorization and audience rules. The owner is the live actor, not an arbitrary input author. DOC04 prechecks a live table for that author_id and maps both precheck and PostgreSQL unique violation of uq_documents_dm_table_per_member to expected CONFLICT with safe reason DUPLICATE_DM_TABLE. Other constraint failures retain their own error handling. Duplicate failure commits no document/revision/notice/receipt. Document category edits into dm_table run the same check excluding the current document; changing category away releases the slot. Soft deletion releases the slot; restoring a deleted table while a replacement occupies it rejects the same conflict atomically.

The existing documents table remains authoritative. P04 installs uq_documents_dm_table_per_member on documents(author_id) WHERE kind='community' AND category='dm_table' AND deleted_at IS NULL. Preflight reports duplicate member/document IDs and fails migration without choosing/deleting an authored document. No synthetic table/backfill is created. DOC04 owns SQL lookup and constraint mapping, DOC06 owns service precheck and transitions; their exclusive repository/command companions cover races. Existing author references and deletion history remain unchanged.

NEST-quest resolves Quest.dmTable through G02 DmTables keyed by the Quest DM member UUID. DOC05 ProductBatchReader.BatchDmTables delegates one correlated set lookup to DOC04 ProductBatchRepository.ReadBatchDmTables. The return has exact key correspondence including duplicates, and uses the same Document audience specification. No live table => nil Value without error; unreadable table => nil Value without revealing UUID/title; SQL/specification failure => opaque dependency error, never an empty-success substitute. Returned readable Document uses the normal document projection/body resolver. No Quest-owned SQL copy, Member-profile fallback, placeholder, or eager body lookup exists.
