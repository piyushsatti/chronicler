## Accepted scope reconciliation

The 162 original identities are independently retained in operation-dispositions.json. Removed product routes must be unmounted, including no-op reconcile and suppression acknowledgement routes. - Personalization R1–R8 supersede historical cosmetic taxonomy. Preferences have theme, independent light/dark/system mode, effects, colorblind-safe palette, reduced motion and density; fixed fonts and flair do not enter GraphQL. equipCosmetic retires. Unlock catalog/ledger survives exclusively for achievements and DM tiers. Grant/reconcile never grants retired cosmetics. Migration removes legacy cosmetic data only after capturing the required local rollback fixture; this is the accepted total purge, not member deletion. Theme contrast is frontend-owned; backend validates finite theme vocabulary and persists settings. Contrast/final first-paint behavior remains outside backend acceptance.
- Documents R1's historical Python wording becomes one specification implemented in Go and SQL; no Python audience copy. Existing marker vectors, author/admin raw-body bypass, live DM/archon distinctions remain authoritative. Codex Artifact/Event/Lore/NPC/Faction use Document commands, category validation and one lifecycle. No Codex table CRUD or second editor API.
- Character owner-only amendment supersedes legacy DM progression/sync broadness. Staff may assess, not edit owner-authored data. Do not use admin bypass for character commands. Character verification is member-owned history with a character consistency check; participation is quest-owned. Member preferences/unlocks remain Member-owned.
- No synthetic timestamps or identifiers. Optional DB references and never-submitted verification times become nullable. Hex link identity is the actual composite `(hexId, documentId, relation)`, not an invented UUID/time. No tile Asset API. Existing mandatory provenance fields without persisted provenance require the migration below; populated legacy unknown provenance is nullable, not invented.
- Queries never reconcile unlocks or acknowledge suppressed inbox rows. Those commands own their transactions. Multiple GraphQL mutations are sequential independent transactions, not request-wide atomicity. Notification failure rolls back its originating business command (owner-approved durability), without savepoint swallowing. External delivery remains durable asynchronous work, separate from in-app read state.
- HISTORY-1/ROWS-1 remains strict: malformed notification or unverifiable historical fact/missing non-document subject fails the requested inbox op with opaque INTERNAL; retain row, do not silently omit/acknowledge/delete/quarantine. Ordinary hidden-document subjects suppress safely and require explicit acknowledgement.
- Operational visibility reports actual persisted/configured evidence: jobs, alerts, attempts, safe failure reasons. Health configuration booleans come from bounded recorded probes or nullable unknown, never optimistic constants. Actions releases/backups are not GraphQL mutations; production deployment remains Actions-only.

## Engineering decisions

E1. Keep existing root names and result type names to reduce unnecessary churn; additive roots use business names from routing. Remove home.questBoard, the deliberately obsolete empty field. Offset pagination remains for collections; notification pagination switches to opaque `(created_at, public_id)` keyset because DateTime-only loses tied rows. This is a deliberate approved-at-Gate-1 breaking engineering correction; cursor contents are authenticated with configured signing key, member scope and unread filter. Invalid/foreign/filter-mismatched cursor = INVALID.

E2. GraphQL expected failures stay apierr values, exposed as errors.extensions.code from the existing six-code vocabulary. Null bubbles according to SDL; a non-null mutation result produces data:null for that failed root. No mutation success union or ok=false for failures. Batch role changes are deliberately atomic all-or-nothing; legacy per-row result shape is retained with ok=true/error=null only on success, not used for partial commit.

E3. All effectful commands require CommandMeta.idempotencyKey (1–128 ASCII `[A-Za-z0-9._:-]`). Canonical actor+operation+key uniqueness; normalized input fingerprint from the one P01 primitive in command-fingerprint-contract.md stored with complete domain receipt, same transaction. Matching replay returns original committed effect/receipt under current authority; mismatch CONFLICT. Unauthorized replay is denied before response. Replay never regenerates notification/job/history or refetches DDB. Store receipts indefinitely in this implementation; later retention is a distinct decision. Stateless preview is a Query and has no replay key. Preserve mark-read's UUID validation, pre-dedup 100 bound, recipient scope and existing timestamp preservation.

E4. Lists default 50/max100, offset0/max10000; members default100; map hex/node/edge list max250/default200; mapView max250; notification max100/default must be supplied (existing limit required). Reject invalid bounds, do not clamp. All finite vocab strings reject unknown values INVALID. Optional filter null/absent means absent; empty string invalid; [] for list filters means match-none; omitted list filter means unfiltered. Arrays are deduped only when semantics are set-valued; order-bearing arrays preserve order. Total = authorized full matching population before paging. Order is fixed and specified in behavior.md.

E5. D27's binding July30 amendment is session-per-task, no lock, superseding its July28 request serialization. In Go each repository query/batch borrows pool connection only for its task; request-scoped Authority/specification travels as immutable input. Never share a pgx Tx across concurrent resolver tasks or hold DB work during remote fetch. A command alone owns one uow transaction including all required cross-domain writes. Clear request loader caches after committed mutations. Correct stale session-audience interface and serving-a-request R1/R2 to current Go pool/task + command-uow wording in Phase2. R3 historical Python union wording becomes Go apierr values/presenter errors exactly as E2. Owner-approved October14 plan explicitly reopens R4 limits; publish that change with bounds and tests, not claim old rejection still governs.
E6. Migration 0003 adds truthful missing fields/provenance, normalized idempotency receipts and event facts, history tables, DDB attempts and finite preferences. No empty placeholders, no rewriting 0001. Follow D16, dedicated histories per owner instead of universal events. Existing rows may lack provenance; represent unknown explicitly and permit ROWS-1 to fail unsupported notices. No automatic notification historical backfill.

E7. Runtime dependencies must fail closed: REQUIRE_DATABASE=1 acceptance harness and production Wire must not serve fake successful data if a dependency is nil. Existing in-memory runtime is permitted only in explicitly selected development/test mode and cannot certify persisted behavior. Deterministic sorted glob SDL merger validates entire schema and duplicate definitions; gqlgen/sqlc/merged schema outputs are orchestrator-owned generated artifacts.

## Resolved product policies

P-DDB (owner accepted): DDB is optional sync/enrichment and never a verification prerequisite. Linkless characters, failed sync attempts and stale mirrors remain eligible under other verification rules. Retain durable attempts and last good snapshot; provenance-backed offline drift fixtures have no scheduled live probes. See ddb-parser-contract.md and POLICY-DDB-OPTIONAL.

P-REWARD (owner accepted): Each player claims PCXP rewards for their own character. Quest closure records entitlements without Character writes. Character claim appends existing progression ledger and updates cached sum, Quest claim state and durable receipt atomically. No cosmetic path, staff grant or new reward notification. See rewards-and-policy.md and POLICY-REWARD-CLOSE/CLAIM.

P-REQUEST (owner accepted): Only the addressed current approved DM decides an addressed request. Admin/platform-owner authority does not override this rule. Notify affected requester and target DM minus actor, atomically with immutable decision history. See POLICY-REQUEST-EXCLUSIVE.

P-ARC-CREATE (owner accepted 2026-10-16): Creating an Arc requires a current approved DM, or the existing admin/configured-owner bypass. A held DM role alone, archon or lieutenant alone, or pending/unapproved DM profile is insufficient. Existing Arc update author/admin admission, including its declared configured-owner bypass, remains unchanged. Role denial is FORBIDDEN.

P-RULE-MANAGE (owner accepted 2026-10-16): Rule creation retains its current Verifier/admin/configured-owner admission. Every later management command requires both current Verifier authority and authorship, unless the existing admin/configured-owner bypass applies. This includes draft update, publish, unpublish, editPublished, audience changes, delete and restore. Author role loss revokes management before completed receipt replay. Non-author Verifiers remain denied. Preserve existing identity disclosure and validation order.

P-QUEST-BRIEF (owner accepted 2026-10-16): Quest commands exclusively own quest_brief lifecycle changes through the existing transaction-bound Document writer. All generic Document writes, including create, update, publish, unpublish, editPublished, audience changes, delete and restore, reject an observable quest_brief with INVALID. This structural refusal applies to admin/configured-owner callers too. Preserve authentication, identity and audience disclosure order before inspecting a protected existing kind. Privileged generic calls do not bypass the owning flow. Current authority and structural admission precede completed replay.

These policies converge on the existing owning command surfaces. They supersede contradictory historical case expectations and handoff prose, but do not rewrite immutable fixtures or establish runtime acceptance. DOC06 and Q06 owners must cover positive admission, denial, role/profile revocation, replay, no-write refusal and shared-transaction rollback. Held-DM preview admission remains unchanged and gains no approval requirement.

E-OWNER (root engineering resolution): optional immutable PLATFORM_OWNER_MEMBER_ID config. Absent grants no owner privilege; present must parse UUID and resolve active member at boot or fail. Current request owner status compares freshly resolved identity, never token roles. No deploy/config production mutation; synthetic fixture supplies admitted UUID. Admin/owner bypass remains excluded for player-character writes.
