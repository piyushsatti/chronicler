# DEV01 supervisor repair contract

**Status:** accepted design. Published schema/config and comment scaffolds do not implement these contracts. Runtime enforcement remains pending the owning implementation tasks and their tests.

Governing pattern: daemonization in a new session. This converges on one supervised compose-log follower; an orphan log client does not fulfill the supervisor contract. DEV01 exclusively owns scripts/dev-stack and scripts/tests/dev-stack-supervisor-integration.sh. It depends only on ROOT-GATE2 and ROOT-TOOL-RUNTIME, and does not depend on GraphQL migrations or resolver work.

Preserve the no-argument entry point, pinned loopback bindings, synthetic local settings and disposable development-stack configuration. Preserve FD8 as the supervisor-lifetime ownership lock and close inherited FD9 in the daemon. Use setsid for the detached supervisor so caller process-group termination cannot kill it. The supervisor owns one log client, reaps its exit, then starts a replacement with bounded retry. Existing database volume remains unchanged.

The bounded companion launches an isolated shell caller and records supervisor PID, owned log-client PID and volume identity. After the caller exits, within ten seconds the supervisor must still be alive in a different session and its ownership lock must remain held. Repeating the no-argument entry point must leave exactly one live supervisor and one owned log client, with unchanged volume identity. Force the owned client to exit; within ten seconds a distinct owned client must be alive, with the same supervisor, and an injected synthetic service log sentinel must appear in the output. No orphan client counts as success. Terminate only test-owned processes during cleanup; fixture volumes are preserved for the repeat assertion. No production release path or credentials are involved.

Startup/repeat, preserved PostgreSQL volume and health204 passed on the old API; recorded supervisor PID disappeared while timeout/docker/compose clients remained orphaned. These findings explain DEV01 and do not establish repaired supervision. These statements are proposed implementation acceptance and do not claim a repaired supervisor or new runtime proof.
